# Feature definition

The following table presents the definition of all the stock features provided with `musif`.

The first column are Python Regular Expressions that match the relevant columns of the
final DataFrame.

The `.+` at the beginning of a pattern stands for the scope prefix of the column:
`Part<Abbreviation>_` (one part), `Sound<Abbreviation>_` (all parts of one instrument),
`Family<Abbreviation>_` (all parts of one family), or `Score_` (all parts). Each row
states the scopes at which the feature is actually produced. Staves that resolve to the
same part abbreviation are treated as one logical part (counts summed, extremes merged).
For a sound performed by exactly one part, every `Sound<X>_` column equals the
corresponding `Part<X>_` column by construction (the sound scope aggregates over that
one part); the `DataProcessor` option `delete_duplicated_sound_columns` drops these
duplicates, keeping the per-part means and part counts.

Conventions used throughout:

* every `_Per` column is a proportion between 0 and 1, not a percentage;
* a value that cannot be computed is **NaN, never 0**: a ratio whose denominator is zero,
  a statistic of nothing, any feature of a part that is not in the score. A 0 is always a
  measured value. The `replace_nans` option of the `DataProcessor` keeps to this: it turns
  an empty cell into 0 only in the columns that count events or give their proportion, and
  only for the scores in which the part has notes (and, for the columns that depend on the
  harmonic analysis, in which the analysis is available);
* pitches are analysed **as they sound**: the part of a transposing instrument (horn,
  trumpet, clarinet...) is transposed by the interval stated in its file before any
  feature is computed, so its scale degrees and ambitus, and the aggregates that include
  it, describe the notes that are heard. A part whose file states no transposition is
  taken as written;
* intervals and melodic motion follow **melodic lines**. In each part, the measures
  written in one voice and the first voice of the measures written in several voices form
  the main line. Every other voice is a line of its own, and it starts anew at each
  passage (a run of consecutive measures in which that voice is written): nothing is
  measured from one passage to the next. A measure in which nothing at all is written for
  the part (the second part of a split staff, while the staff shows a single line) ends
  the main line in the same way;
* chords (double stops, keyboard chords) are excluded from note-based features, although
  a measure containing only chords still counts as sounding;
* scale degrees in minor keys are measured against the **natural** minor scale (the
  signature that the key has by modern convention, which is not always the one notated),
  so a raised leading tone is `Degree#7`. A degree column therefore does not mean the same
  in the two modes: `Degree7` is the leading tone of a major key and the subtonic of a
  minor one. The same holds, passage by passage, for the degrees relative to the local
  key. Compare arias across modes with `Mode` at hand;
* rates are given in **two units of time**. The *beat* is the one of each time signature
  (`NumberOfBeats`: four in 4/4, two in 2/2 and 6/8, one in 3/8), and a rate per beat
  (`Density`, `RhythmInt`, `DottedRhythm`, `DynGrad`, `DynAbruptness`,
  `HarmonicRhythmBeats`) changes with the metre a piece is notated in: the same notes
  written in 2/2 give twice the density per beat they give in 4/4. The columns ending in
  `Quarters` give the same rates per *quarter note*, which is the same length in every
  metre; use them to compare arias in different metres. Neither unit knows the tempo;
* every feature describes **the notated score, read once through**: repeats, *da capo* and
  *dal segno* instructions are not followed (unless `expand_repeats` is set). In an aria
  whose reprise is not written out, the opening section is on the page once although it is
  performed twice, so proportions and means weigh it less than a score with a written-out
  reprise does. `RepriseInstruction` tells the two kinds of score apart;
* the **`Score_`** value of a feature covers every part of the score, and depends on which
  parts those are. Where it pools the notes of all parts (intervals, scale degrees,
  ambitus), it is dominated by the parts with most notes, usually the strings. Where it
  is a mean over parts (`Density`, `RhythmInt`, `DottedRhythm`, the dynamics), a pair of
  horns that plays twenty notes weighs as much as the first violins, and an aria with
  winds comes out less dense than the same music without them. To compare arias of
  different scoring, use the columns of the parts they share (`PartVnI_`, `PartBs_`,
  `FamilyStr_`...) rather than `Score_`;
* in windowed extraction only complete windows are analyzed (a tail shorter than one
  window is skipped) and per-window rows have `Measures` equal to the window size.

Finally, the _Stock module_ column lists the module distributed in `musif` that
generates each feature. The stock feature modules are: `core`, `ambitus`, `melody`,
`tempo`, `density`, `texture`, `harmony`, `lyrics`, `scale`, `scale_relative`, `key`,
`dynamics`, `rhythm` and `music21`, plus the basic modules `scoring` and
`file_name_generic`.

Note that none of these features works on percussion instruments.

In addition to the features in the present page, the features in the `'music21'` stock
module (first row of the below table) provide all the features from [`music21.features.native`](http://web.mit.edu/music21/doc/moduleReference/moduleFeaturesNative.html).

## Notes for typical notated corpora

On the opera-seria corpus used to validate these features (and most notated
corpora of the period), several column families are structurally degenerate;
they are kept for generality but carry no information there:

* `DoubleAugmented`/`DoubleDiminished` interval columns and
  `DoubleDottedRhythm` are all zero.
* `m21_ChordBassMotionFeature_0` is the constant `1.0` sentinel that `music21`
  emits when a score contains no chord-symbol objects (notated scores never
  do); features `_1` through `_11` are zero.
* the processed `Degree_.+_Dasc`/`_Ddesc` columns are zero, so
  `Nonat = Asc + Desc` there.
* rare chromatic degrees and interval qualities are all-zero on most corpora;
  wherever a directional count is all-zero, its `All` twin equals the other
  direction.
* `Presence_of_X` is constant 1 for instruments present corpus-wide (voices
  are excluded from `Instrumentation` by design), and equals
  "`Sound<X>_NumberOfParts` is not NaN" row by row.
